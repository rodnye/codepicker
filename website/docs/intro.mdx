# Introduction to Codepicker

**Codepicker** is a bidirectional CLI tool that transforms your codebase into structured Markdown, and vice versa. It is specifically designed to make working with Large Language Models (LLMs) on real-world projects **fast, predictable, and frictionless**.

## Why Codepicker?

Working with LLM chats on existing codebases is usually a tedious process:

1. Open files manually.
2. Copy paths and content.
3. Paste into the chat.
4. Repeat the process.
5. Reconstruct the changes manually.

Even with IDE agents, you are often limited to their specific workflow. **Codepicker** removes this friction, allowing you to move context in and out of your project with a couple of commands.

## Main Features

- ⚡ **Instant Context**: Copy entire project sections with the `-c` flag.
- 🔄 **Bidirectional Flow**: The `apply` command converts Markdown back into files on your disk.
- 🧠 **Noise Tolerant**: Ignores explanations and extra text, keeping only valid code.
- 🛡️ **Smart Wrapper**: Prevents broken code blocks by adjusting the number of backticks.
- 🎯 **Precision Controls**: Limit lines, add numbers, use absolute paths.
- 📄 **Documentation Mode (`-D`)**: Helps LLMs follow the Codepick format correctly.
- 📦 **Binary Safe**: Avoids dumping illegible content from binary files.
- 🙈 **`.gitignore` Aware**: Respects your repository by default.

## How does it work?

Codepicker uses a structured format called **Codepick Format**. Each file is represented as a code block where the first line indicates the target filesystem path.

````markdown
```ts
// src/index.ts
console.log('Hello World');
```
````

This format is perfectly parseable and, unlike diffs or traditional response formats, it packages the complete file content, eliminating ambiguities.

# LLM Workflow

Codepicker shines when integrated into your daily workflow with Large Language Models (LLMs) like ChatGPT, Claude, or Gemini. Here's how to get the most out of it.

## The Context Problem

LLMs have limited context windows and often "forget" or hallucinate file paths when asked to modify code.
Additionally, manually copying and pasting dozens of files is error-prone.

## The Solution: Codepicker

### Step 1: Extract Context

Select the files relevant to your task and copy them to the clipboard:

```bash
codep -cD "src/services/**/*.ts" "src/views/**/*.tsx"
```

:::info The `-D` flag
The `-D` flag (or `--include-docs`) is **crucial**. It adds the Codepick format specification at the end of the prompt. This "trains" the LLM on the spot so it returns the response in the exact format that `codep apply` can process.
:::

### Step 2: Interact with the LLM

Paste the content into your LLM and give it clear instructions:

```text
Here is the context of my project.
Please modify the view to add a modern blue button with a shadow.
IMPORTANT: Return the modified files strictly using the Codepick format.
```

### Step 3: Apply the Changes

Once the LLM returns the response, copy it and run:

```bash
codep apply -c
```

Done! Your files will be automatically updated on your filesystem.

## Tips for Better Results

1. **Be specific with patterns**: Don't extract the whole project if you only need to modify a specific module. This saves tokens and reduces LLM confusion.
2. **Use `--dry-run`**: If you're unsure about the changes the LLM proposes, use `codep apply -c --dry-run` to see which files would be affected before applying them.
3. **Control the size**: If a file is too large, use `-l 100` to limit the lines and give the LLM only the structure or relevant parts.
4. **Respect `.gitignore`**: By default, Codepicker ignores `node_modules`, `.git`, etc. Don't use `--no-gitignore` unless strictly necessary, to avoid saturating the LLM's context with irrelevant files.

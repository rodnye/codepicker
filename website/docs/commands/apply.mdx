# Apply Command

The `apply` command takes a Markdown document (or clipboard content) and extracts the code blocks to write or update them on your filesystem.

## Basic Syntax

```bash
codepicker apply [options] [dump-file]
```

## Available Options

| Option             | Description                                                                     |
| ------------------ | ------------------------------------------------------------------------------- |
| `[dump-file]`      | Markdown file containing the code blocks.                                       |
| `-c, --clipboard`  | Reads the code blocks from the clipboard instead of a file.                     |
| `-d, --dir <path>` | Base directory where files will be written (defaults to the current directory). |
| `--dry-run`        | Previews the changes without writing anything to disk.                          |

## Typical Workflow

1. **The LLM generates code**: Your LLM returns a response in Codepick format.
2. **You copy the response**: You select and copy the complete code block from the LLM's response.
3. **You apply the changes**:
   ```bash
   codep apply -c
   ```

## Practical Examples

### Apply from Clipboard

```bash
codep apply -c
```

### Apply from a File

If you saved the LLM's response in a file:

```bash
codep apply response.md
```

### Preview Changes (Dry Run)

Before overwriting files, you can see which files will be created or updated:

```bash
codep apply -c --dry-run
```

### Apply in a Specific Directory

Useful if you want to apply changes in a different branch or a test directory:

```bash
codep apply -c -d ./test-environment
```

## Handling "Dirty" Responses

One of the great advantages of `apply` is its **noise tolerance**.

If the LLM's response includes explanations, introductory text, or comments outside the code blocks, **Codepicker will safely ignore them**. Only the valid code that is inside correctly formatted code blocks will be extracted and written.
